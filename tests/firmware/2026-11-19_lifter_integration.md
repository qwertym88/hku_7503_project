# 正常底盘固件加入连续舵机升降

2026-11-19，Asia/Shanghai。本轮只修改/构建软件，未操作开发板、未烧录、未发轮或舵机动作命令。

## 用户提供的实际条件

S1/GPIO8，MG996R 360°连续旋转舵机；用户观察顺时针为抬升、逆时针为下降，单程90°，初始最低点。限位为机械挡块，无电信号；用户确认停转/断电能保持载荷。保持能力尚未由本轮独立带载测试验证。

## 最终实现

- 正常 `/chassis` 新增 `/lifter` UInt8订阅，1升0降、其他拒绝。独立 `lifter` 组件包含可原生编译的状态控制与ESP-IDF PWM/任务封装。
- 默认禁用。启用且有效时只输出配置中立值，须调用arm服务解锁；无标定时仅允许有限时长jog。中速采用1500±200µs作为待验证起点，方向/速度与90°时间均须实测。
- 三个标准服务：arm Trigger、stop Trigger、jog SetBool（true升、false降）。stop不以0复用，不改变原UInt8契约。服务成功只是请求接受/处理，不等于机械到位。
- 同向完整目标幂等，不延长截止；运动中反向拒绝，点动/中途停止后位置未知，完整90°动作拒绝，防止从半程继续盲转90°。最低点启动为用户假设，不是传感器读数；诊断position_confirmed恒false。
- 10ms独立任务及心跳租约，运行截止后中立停转，丢失主循环心跳480ms/通信错误/轮故障/PWM错误会停止并锁存。动作截止迟到超过30ms记超时，不能伪报完成。超时/故障不替代物理急停。
- 轮电机入口新增由lifter独占的互锁，原子拒绝并发非零轮速；中立输出后的约200ms仍锁住底盘。结束后释放不会恢复旧轮速，需要新命令。解锁/启动前轮输出关闭且反馈连续200ms接近0。
- 三服务、2订阅、3发布，5话题、7 executor句柄；扩大诊断缓冲至1792，自定义XRCE MTU2048，构建包装脚本检查MTU以避免共享库/头文件旧缓存。原始odom/IMU行为保留。

## 软件验证

1. `lifter_control_test.c`编译运行实际纯C控制器：启动不动、最低点幂等、完整升/降、重复不延时、反向/非法命令拒绝、无标定仅jog、点动位置未知、取消、未知位置拒绝完整动作、超时/通信/轮故障锁存。
2. `check_lifter_driver.py`编译实际 `lifter.c`：禁用不初始化PWM，启用中立、轮停稳/主循环租约检查、先锁轮后舵机输出、定时中立、停稳互锁、stop/arm、PWM失败强制低及硬故障不能被stop清除。
3. `check_lifter_ros.py`编译实际主程序回调及格式化表达式：正确绑定UInt8/Trigger/SetBool语义、显式arm、重复目标、非法值拒绝、非零cmd_vel被升降拦截、轮零速不取消升降、stop/方向点动、诊断JSON和MTU边界。
4. `check_motor_control.py`增加实际轮驱动互锁回归，验证lift inhibit期间不写PWM、解除不自动恢复旧命令；原反馈故障和480ms轮命令看门狗保留。
5. 已有IMU发布、静态校准、台架工具、安装停转程序回归检查通过。
6. ESP-IDF5.1.2 / esp32s3默认禁用与启用/已配置时间的编译夹具均通过。启用夹具的500/700ms仅用于验证编译路径，不是实物标定结果，未烧录；最终构建已恢复项目sdkconfig：ENABLE=n、TRAVEL_CALIBRATED=n、UP/DOWN_MS=0。应用哈希见[构建记录](2026-11-19_lifter_build.json)。

当前没有电流堵转检测或电气到位反馈，定时截止不能识别所有提前卡滞。没有硬件GPIO/PWM测量、服务端连通、90°精度、实际停转时间、供电或带载20循环证据，不记作实机通过。SDK中的micro-ROS依赖有原有告警，编译通过不等于第三方库无告警。
