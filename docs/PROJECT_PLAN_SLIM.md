# 精简执行计划（保底 A range 版）

> 目标：**5 人团队，用最小可行范围，稳定跑通"A 档自动导航 + 自动取放"**。
> 原则：**能少做就少做；能复用现成组件就不自己写；接口只留够用的。**
> 编制：2026-10-22　｜　提交：2026-11-26（周四 17:00 实物 / 23:59 Moodle）

---

## 1. 保底目标定义（什么叫"成功"）

**一句话验收**：机器人放在起点 → 扫到 `START` 自动启动 → 自动开到一个货架处 → 扫码确认 → 举升起货架（全程离地）→ 自动送到目的区放下 → **不撞墙**。能在 3 分钟内**至少完成 1 个货架**、争取 2–3 个。

达到这个，A 档（自动导航并限时完成）就成立。**速度、美观、多货架都不是保底目标。**

**优先级（时间不够就从上往下砍）**
1. 底盘能动 + 里程计可用
2. 举升能可靠举起/放下（**最关键**）
3. 扫码能识别 `START` / `RACKx_xxxx`
4. 已知坐标点之间能自主到达（误差 ±5cm 内）
5. 串成完整自动流程
6. 连续 5 次不掉链子
7. （附加，几乎零成本）`teleop_twist_keyboard` 作为 B 档手动兜底
8. 外观美化 / 多货架一次搬 / 自定义 UI —— **不做**

## 2. 范围裁剪：做什么 / 不做什么

| ✅ 做 | ❌ 不做（明确砍掉） |
|---|---|
| 4 麦轮底盘 + 1 舵机简单举升 | 复杂连杆/自适应多自由度机构 |
| 4 个固定货架按已知坐标顺序取 | 动态探索、SLAM 在线建图打比赛 |
| 起点扫描用相机 QR 识别 | 视觉测距/视觉伺服精细对准 |
| 雷达 + 现成 Nav2 做点到点导航 | 自己写路径规划/控制器/自定义插件 |
| 单货架往返为一个循环 | 一次搬多个货架 |
| 物理急停开关 | `/estop` 话题、电量上报、日志服务 |
| 简单外壳（能用就行） | 精细外观设计 |
| `teleop_twist_keyboard` 手动兜底 | 自定义手柄/手机遥控 App |

**关键取舍**：**举升机构第 1 周就要打样**——它是唯一不可替代、坏了就全盘皆输的环节。其他都可以后面补。

## 4. 精简架构（只有两层）

```
      Raspberry Pi 5  (ROS 2 Jazzy)                     ESP32 (micro-ROS)
 ┌──────────────────────────────────────┐          ┌───────────────────────┐
 │  camera_ros ──► qr_node ──► /qr      │          │  4×电机 逆解 + PID     │
 │                                       │  USB     │  编码器 → /odom        │
 │  MS200 驱动 ──► /scan                 │◄────────►│  舵机 ← /lifter        │
 │                                       │  串口     │                       │
 │  AMCL + Nav2  ──► /cmd_vel            │          └───────────────────────┘
 │                                       │                    │
 │  mission_node（状态机，核心）──► /lifter│              4 麦轮 + 1 舵机
 └──────────────────────────────────────┘
```

**刻意的不规范（省事，不是错）**
- 只用标准消息类型（`Twist` / `Odometry` / `LaserScan` / `String` / `UInt8`），**不定义自定义消息**。
- 不做 QoS 设计、不做多包拆分、不做 launch 参数化框架；一个 `mission` 节点里把状态机写清楚即可。
- QR 解码与任务状态机**可以放同一个进程**，只要彼此函数边界干净（便于两人分别开发）。
- 定位不追求完美：**雷达定为主，里程计为辅**。

## 5. 最小接口表（一共 5 个）

| 话题 | 类型 | 谁发 → 谁收 | 说明 |
|---|---|---|---|
| `/cmd_vel` | `geometry_msgs/Twist` | 导航 → 固件 | 速度指令 |
| `/odom` | `nav_msgs/Odometry` | 固件 → 导航 | 里程计（含 yaw） |
| `/scan` | `sensor_msgs/LaserScan` | 雷达驱动 → 导航 | 激光 |
| `/qr` | `std_msgs/String` | 感知 → 任务 | 解码结果，如 `RACKA_4X6M` |
| `/lifter` | `std_msgs/UInt8` | 任务 → 固件 | `0`=放下，`1`=举起 |

> 就这 5 个。**不变的就是这些**；谁想加话题，先在站会说一声。

## 6. 最小任务状态机

```
启动 → 等 /qr == "START" 或 "RACKx_..."（任一，容错）→ t0 = now
  循环（按坐标从近到远）：
    ① GOTO_RACK   导航到货架前 1 个固定停靠点
    ② CHECK_QR    等 /qr 出现对应 RACKx_（超时 5s 就继续，不卡死）
    ③ LIFT        /lifter=1，等 2s
    ④ GOTO_DEST   导航到目的区固定点
    ⑤ DROP        /lifter=0，等 2s
    ⑥ 还有货架且剩余时间够 → 回 ①
  结束：全部送完 或 3 分钟到 → 停车
每一步都有超时；超时就跳过/回退，绝不原地卡死。
```

**兜底规则**：若某货架连续 2 次取失败，直接跳过取下一个，**先保证完成数量**。

## 8. 主要风险与兜底（只留 6 条）

| 风险 | 兜底做法 |
|---|---|
| **1 个舵机举不动 / 卡死** | 弹簧或配重辅助；连杆增力；托叉可调；M1 就验证，坏了立刻改机构 |
| **货架尺寸/重量不明** | 托叉做可调（开口 + 高度）；拿到实物当天实测迭代 |
| **里程计打滑漂移** | 以雷达定位为主；停靠点用 QR 就近修正 |
| **撞墙扣分** | Nav2 膨胀半径设大、限速、精停用低速 |
| 3 分钟跑不完 | 就近取货；单步超时跳过；先保数量 |
| 团队进度不同步 | 每日联调 + 5 个话题冻结 + 单集成机 |
