## 0. 一页结论（TL;DR）

- **我们要交付的不是"一个能动的小车"，而是"一套能在 3 分钟内稳定完成 取货架→举升→送到目的区 的自主系统"。** 评分权重里"整体小组 25% + 演示 10%"，其中演示分是**按完成数量和时间档位**给的，所以**稳定性 > 极限速度**。
- **最大的技术风险不是导航，而是"举升机构"**：官方只提供 **1 个 MG996 舵机**，却要求举起货架且**运送全程不触地**。这是本项目的设计核心，必须第 1 周就出机构方案并打样验证。
- **最大信息缺口是"货架几何与场地实测尺寸"**（图纸尺寸是栅格图，无法完全精确读取）。机构必须做成**可调/自适应**，并在拿到实物后第一时间实测。
- **建议的推进节奏**：W1 冻结需求+出架构，W2 机械打样+各子系统 bring-up，W3 端到端跑通"单货架"，W4 全流程+调优，W5 彩排+文档+收尾。
- **必须同时准备"自动模式(A)"和"手动模式(B)"** 两套演示能力——这是评分表里明确分开给分的。

## 1. 任务解读（Requirements 摘要）

### 1.1 目标
设计并制作一台**智能轮式物流机器人**，集成 ESP32 + Raspberry Pi、激光雷达、摄像头与**举升装置**，能：
1. 用摄像头扫描起点 QR → 自动启动；
2. 用激光雷达自动导航到货架区域；
3. 扫描货架 QR 定位货架→举升→运送到目的区（**货架不得触地**）；
4. 3 分钟内重复上述过程直到所有货架送达。

### 1.2 交付物（缺一不可）
1. 实体智能轮式机器人（已测试）；
2. 全部 CAD 文件，含 SolidWorks **pack-and-go** 压缩包；
3. 全部控制程序（ROS 2 Jazzy 文件 + micro-ROS 文件）；
4. 项目物料/工具归还（塑料箱、显示线、Pi5 27W 电源、USB3.2 读卡器、充电器、电源适配器、未使用零件）；
5. PowerPoint；
6. **每个 QR 码解码结果的屏幕截图**（QR 文档明确要求，用于证明扫描功能）。

## 2. 硬约束与验收清单

### 2.1 硬约束
- 整车外廓 **≤ 300 mm × 300 mm × 180 mm**（含举升机构收拢状态、天线、线缆）。
- **仅提供一套元器件**，损坏即不可替换（尤其 micro-ROS 板：电机线**颜色接错会烧板**）。
- 货架位置固定且**坐标 (x, y) 提前已知**——这让"导航"本质上是"已知点的精确停靠"，而非未知探索。
- 场地约 **3020 × 2000 mm**（图纸标注，需实测确认）。
- 供电必须**电池供电**（Pi5 电源适配器仅用于开发阶段）。

## 3. 比赛规则与得分策略

### 3.1 规则要点
1. 以组为单位，一台机器人 = 一名参赛者。
2. 机器人扫描**起点 QR**后自动开始识别/取货，**计时开始**。
3. 导航到货架区 → 扫货架 QR → 定位 → 举升 → 送到目的区。
4. **3 分钟内重复**直到所有货架送达。
5. **运送途中货架不得触地**。
6. 机器人与货架撞墙：**每次 -2 分**。
7. 结束时统计目的区内货架数，**每个 +5 分**，并参与全组排名。

### 3.2 得分模型与策略
- 设有 A/B/C/D 四个货架，理论上限 **4×5 = 20 分**；每次撞墙 -2 分。
- **一次撞墙 ≈ 丢掉 0.4 个货架的收益**，而目的区停靠精度只有 ±几厘米的容差，所以**策略是"稳、准、少碰撞"，不是"快"**。
- **取货顺序优化**：货架坐标已知 → 这是一个小型路径规划（最近邻/2-opt/TSP）。建议实现"按距离 + 当前朝向代价"排序取货，减少无效转身。
- **时间预算（3 min）建议分配**：单个货架目标 ≤ 30s（导航 15s + 对准扫码 5s + 举升 4s + 送达 6s），留 30s 冗余。
- **是否需要一次带多个货架**：取决于货架尺寸与举升台面积；若可叠放/并排，收益翻倍，但风险高。**列为"可选增强（stretch goal）"，主方案仍是单货架往返。**

### 3.3 场地理解（待实测确认）
- 起点区与目的区为场地上的标记区域；四个货架 A/B/C/D 位置固定且坐标提前公布。
- 图纸栅格图中可读到的标注：整体宽约 3020、高约 2000；目的区一侧标注 800/350 量级，起点区一侧标注 600/210 量级。**这些数字来自图像 OCR，仅供建模参考，进场后必须用卷尺实测复核。**（详见附录 A）

### 4.2 机械子系统
- **底盘**：300×300×180 上限内布置 4 麦轮 + 4 电机 + Pi5 + micro-ROS 板 + 电池 + 舵机举升机构。重心尽量低并居中，电池放底部中央压重心。
- **举升机构（关键路径）**：唯一执行器是 1 个 MG996。候选方案：
  1. **四连杆/曲柄-摇杆举升台**（舵机旋转→连杆抬升平台）：结构简单，速比可由连杆长度放大；
  2. **丝杠/齿条 + 舵机驱动**：自锁性好，但舵机行程有限，需齿轮/连杆转换旋转→直线；
  3. **弹簧辅助 + 舵机解锁/限位**：用储能弹簧承担重力，舵机只做释放/锁定，**大幅降低舵机负载**（推荐评估）。
  - 选型依据：**货架重量未知** → 必须做可调托叉高度/开口宽度，并用配重或弹簧补偿。
- **托叉/平台**：前端开口式叉臂（fork）便于驶入货架下方；表面加防滑垫，防止运输中滑落。
- **传感器布局**：激光雷达置于车体最高处、水平 360° 无遮挡（注意不要被举起的货架挡住扫描面）；摄像头前置、尽量靠近车体中线并略向下俯视以适应近距离 QR 扫描。
- **美观性（评分项）**：亚克力激光切割外壳 + 3D 打印件，线缆隐藏，边缘倒角。

### 4.3 电子与供电
- **供电拓扑**：7.4V 锂电 → micro-ROS 控制板 → (a) 板载稳压给 ESP32/电机驱动/舵机，(b) USB C→C 给 Pi5 供电。
- **功耗预算**：Pi5（峰值 ~5W+，摄像头/雷达附加）+ 4 电机（堵转瞬时大）+ 舵机（堵转 ~2.5A@6V）。**必须实测续航**，3 分钟比赛 + 热身需留 2× 余量。
- **接线纪律**：电机线**白接头→控制板、黑接头→电机**；上电前双人复核。舵机三线（黑GND/红+5V/黄PWM）方向正确。
- **安全**：硬件急停开关；软件 `/estop` 话题；电池低压告警阈值。

### 4.4 固件层（ESP32 / micro-ROS）
- 编译 micro-ROS（Yahboom 官方固件/示例为起点），在 Pi5 上跑 `micro_ros_agent` 通过 USB 串口桥接。
- 功能：
  - 订阅 `/cmd_vel`（geometry_msgs/Twist）→ 麦轮运动学逆解 → 4 电机 PWM；
  - 读取 4 路编码器 → 前向运动学 → 发布 `/odom`（含 yaw）；
  - 发布 `/wheel_state`（各轮转速/电流，便于诊断）；
  - 订阅 `/lifter_cmd` → 舵机 PWM 举升/放下，带**限位检测与堵转保护**；
  - 发布 `/battery`（电压）。
- 麦轮运动学：vx, vy, ω → 四轮线速度（注意左右轮安装方向与轮子"左/右旋"配对，装错会导致平移方向相反，是经典坑）。

### 4.5 上位机层（Raspberry Pi 5 / ROS 2 Jazzy）
- **camera_ros**：`libcamera` + `camera_ros` 需**源码编译**。发布 `/camera/image_raw`。
- **QR 识别节点**：OpenCV `QRCodeDetector`（或 `wechat_qrcode` 增强）→ 发布 `/qr_decoded`（std_msgs/String）；同时发布解码置信度与二维码像素尺寸（用于**估算距离做视觉对准**）。
- **雷达节点**：MS200 ROS2 驱动 → `/scan`。
- **建图/定位**：`slam_toolbox` 赛前建图 → 保存 map → 比赛中用 `AMCL` 定位（麦轮打滑会导致里程计漂移，务必用雷达定位兜底）。
- **导航**：`Nav2`（controller/planner/costmap）。**关键参数**：把机器人 footprint 设准、膨胀半径设大以防撞墙（撞墙 -2 分）；终点停靠用精确 pose goal + 低速接近。
- **任务状态机**：见 §4.7。
- **可视化/调试**：RViz2（可通过 Wi-Fi 热点从 PC 远程看），`ros2 bag` 录制比赛日志用于复盘。

### 4.6 接口契约（团队并行开发的"合同"，先冻结）
| 话题 | 类型 | 方向 | 发布者→订阅者 | 说明 |
|---|---|---|---|---|
| `/cmd_vel` | `geometry_msgs/Twist` | Pi → ESP32 | nav2/teleop → 固件 | 速度指令 |
| `/odom` | `nav_msgs/Odometry` | ESP32 → Pi | 固件 → 定位 | 轮式里程计 |
| `/scan` | `sensor_msgs/LaserScan` | 雷达 → Pi | 驱动 → Nav2 | 激光数据 |
| `/camera/image_raw` | `sensor_msgs/Image` | 相机 → Pi | camera_ros → QR节点/RViz | 图像 |
| `/qr_decoded` | `std_msgs/String` | QR节点 → 状态机 | QR节点 → mission | 解码字符串 |
| `/lifter_cmd` | `std_msgs/Bool`/自定义 | 状态机 → ESP32 | mission → 固件 | 举升/放下 |
| `/battery` | `sensor_msgs/BatteryState` | ESP32 → Pi | 固件 → 监控 | 电量 |
| `/estop` | `std_msgs/Bool` | 任意 → 固件 | 安全 | 急停 |
| `/mission_state` | `std_msgs/String` | 状态机 → 全系统 | mission → RViz/日志 | 状态可观测 |

> **约定：谁发布、谁订阅、QoS、频率，全部写进 `docs/INTERFACES.md` 并在 W1 冻结。** 这是 8 人并行的前提。

### 4.7 任务状态机（Mission Controller）
```
IDLE
 └─(检测到 START QR)→ RUNNING: t0=now
    ├─ PLANNING         : 按已知坐标排序剩余货架（最近邻）
    ├─ GOTO_APPROACH    : Nav2 到货架前方对准位姿
    ├─ ALIGN_AND_SCAN   : 微调 + 扫码确认 RACKx_xxxx（未识别则重试 N 次并重定位）
    ├─ LIFT             : 举升到位（限位/超时保护）
    ├─ GOTO_DEST        : 带载导航至目的区（低速、加大膨胀半径）
    ├─ PLACE            : 放下货架，确认已落入目的区
    ├─ CHECK_TIME       : 剩余时间 > 阈值且仍有货架 → 回到 PLANNING
    └─ DONE             : 全部送达 / 超时 → 停车
 异常：任何步骤超时 → 记录 → 退回上一稳定状态或安全停车
```
- **超时与重试**是可靠性的核心：每个状态设最大时长，避免"卡死浪费 3 分钟"。

## 10. 环境搭建与前置准备（W1 内完成）

1. **Pi5**：安装 64-bit Raspberry Pi OS → 安装 **ROS 2 Jazzy**（官方 apt 源）→ 验证 `ros2 topic list`。
2. **交叉编译环境**：Arduino IDE / PlatformIO 配置 ESP32 + micro-ROS 依赖（锁定版本）。
3. **micro-ROS agent**：Pi5 上构建并验证与 ESP32 的 USB 串口通信（固定设备名 udev 规则）。
4. **camera_ros**：源码编译 `libcamera` + `camera_ros`，验证出图（这是已知的难点，排在最前）。
5. **MS200 雷达驱动**：Yahboom 提供 ROS2 驱动，验证 `/scan`。
6. **Nav2 / slam_toolbox**：安装并跑通仿真/空场。
7. **OpenCV + QR**：`python3-opencv` 或 `cv_bridge`，写最小解码 demo。
8. **开发辅助**：PC 上 RViz2/ros2 CLI 通过 Wi-Fi 热点连 Pi5；`ros2 bag`、`rqt`。
