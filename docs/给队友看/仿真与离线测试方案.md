# 仿真与离线测试方案（M3 / M4 必读）

> **一句话回答：M4 有必要（但必须复用现成的，别自建）；M3 没必要。**
> 两者的答案相反，因为**导航是几何问题，扫码是图像问题**。

---

## 0. 先分清三类"不在场地也能干活"的手段

| 档 | 手段 | 成本 | 能测什么 | 测不了什么 |
|---|---|---|---|---|
| **T0** | **Mock 节点**（假 `/odom` `/scan` `/qr`） | ≈0 | 状态机、接口对接、启动流程、异常分支 | 一切物理相关 |
| **T1** | **Bag 回放**（真机录一次，离线重放） | 半天 | AMCL 定位、costmap、全局规划、参数调优 | **闭环控制**（车不会动） |
| **T2** | **Gazebo Harmonic 仿真** | 1–2 人日 | 闭环导航、完整任务流程、演示录屏 | 真实打滑/光照/机械误差 |

**关键：T0 和 T1 的性价比远高于 T2，必须先做。** T2 是加分项，不是前置条件。

---

## 1. M4：有必要，而且现在几乎"免费"

### 1.1 为什么值得

我们**不总能进场地**（实验室开放时间、场地搭建、其他组占用），而 Nav2 的参数调优需要大量反复试跑。仿真是唯一能"随时跑"的路子。

### 1.2 为什么现在便宜了——linorobot2 已经把仿真栈做完了

我核对了 `linorobot2` 的 `jazzy` 分支（实际 clone 确认）：

| 事实 | 证据 |
|---|---|
| **用的是 Gazebo Harmonic（新版）+ `ros_gz`，不是 Gazebo Classic** | `linorobot2_gazebo/launch/gazebo.launch.py` 引入 `ros_gz_sim` 的 `gz_sim.launch.py` |
| **自带麦轮底盘模型** | `linorobot2_description/urdf/robots/` 下有 **`mecanum.urdf.xacro`**（还有 2wd/4wd） |
| **Gazebo 原生支持麦轮驱动** | `urdf/controllers/omni_drive.urdf.xacro` 使用 **`gz::sim::systems::MecanumDrive`** |
| **传感器已配好** | `urdf/sensors/`：`gpu_lidar`、`rgbd_camera`、`imu_sensor` |
| **仿真与真机共用同一套 YAML** | 官方 README："The same YAML files are used by both the physical robot and the Gazebo simulation, so **tuning in simulation transfers directly to hardware**" |
| **能把真实场地搬进仿真** ⭐ | README："Convert a floor plan image **or a SLAM-generated map** directly into a Gazebo world" |
| 两个工具 | `image_to_gazebo`（GUI：图纸图片 + 交互校准真实比例 → 生成世界）；`create_worlds_from_maps`（**批量 CLI：把 `linorobot2_navigation/maps/` 里所有 SLAM 地图转成 Gazebo 世界**） |

### 1.3 这条对我们的意义（很重要）

- **仿真不再依赖 M1 的 CAD**：先用 linorobot2 的 `mecanum` 模板 URDF 起仿真，等 M1 出了 CAD 再替换网格与尺寸。**M4 的仿真进度不会被 M1 卡住。**
- **场地世界可以从我们自己的 SLAM 地图生成**：先在真实场地建一次图，之后就能在"同一布局"的仿真里反复练。这正好解决"不能总进场"。
- **麦轮在仿真里是真麦轮**：`MecanumDrive` 插件能模拟侧移。也就是说，**仿真里可以放心试横移**——而保底阶段真机不开横移。**仿真比真机更能验证麦轮潜力**（这也给了"横移"一个低风险的试验场）。
- 还能顺带产出**演示录屏**（PPT/答辩用），不必每次都搬真车。

### 1.4 成本与护栏

- **安装**：`ros-jazzy-ros-gz`，装在 **Ubuntu 24.04 的 PC/VM 上，不装在树莓派上**（Gazebo 在 Pi 上跑不动）。
- **成本**：把 `mecanum` base + 场地世界跑通，估 **1–2 人日**（因为配置都是现成的）。
- ⚠️ **护栏**：**仿真投入上限 2 人日**。它是"没场地时的替代品"，不是交付物。**绝对不许为了调仿真而推迟真机调试。**
- ⚠️ **`use_sim_time` 陷阱**：仿真必须 `use_sim_time: true`，真机是 `false`。两者混在一个 ROS 域会出诡异问题 → **仿真单独开 `ROS_DOMAIN_ID=197`**（我们已有此约定）。

## 2. M3：没必要做仿真

### 2.1 为什么

扫码**不是几何问题，是图像处理问题**。Gazebo 的相机渲染**帮不上解码**：

| 想验证的东西 | 仿真相机能帮吗 |
|---|---|
| 解码算法对不对 | ❌ 渲染图太"干净"，测不出真实难例 |
| 模糊/光照/反光下的鲁棒性 | ❌ 仿真的光照与噪声模型和场地差得远 |
| 不同距离/角度能不能扫到 | ⚠️ 勉强，但不如真实照片可信 |
| 与状态机的集成是否通 | ✅ 这个有用（但用 T0 mock 更快） |

**为 M3 搭一套仿真相机，成本高、保真度低、收益接近零。**

### 2.2 M3 应该做什么：**离线图像/视频回放测试集**

这才是 M3 的"仿真替代品"，而且**比仿真更贴近真实**：

```text
tests/qr_dataset/
├─ START/   *.jpg      # 每个码拍若干张
├─ RACKA_4X6M/
├─ RACKB_.../
├─ RACKC_.../
├─ RACKD_.../
└─ END/
```

**采集要求**（这就是 M3 的"难例集"）：

| 维度 | 取值 |
|---|---|
| 距离 | 近距离 / 典型停靠距离 / 偏远处 |
| 角度 | 正对 / 左右各偏 ~30° / 上下各偏 ~20° |
| 光照 | 正常 / 偏暗 / 侧向反光 |
| 模糊 | 静止清晰 / 模拟行进中的轻微拖影 |

**用法**：
```bash
python3 tools/qr_eval.py tests/qr_dataset/    # 遍历所有图，打印识别率
```
- 这一套**不需要相机、不需要 ROS、不需要场地**，任何人在任何机器上都能跑。
- 每次改了解码参数，跑一遍就知道有没有变差（回归测试）。
- **手机就能采集**（不用等机器人装好相机）。

> 这比"把二维码贴到货架上、推着车在场地里试"高效得多，而且是**可重复**的。

### 2.3 顺带的一个红利

如果 **T2（Gazebo 场地）** 建起来了，M3 可以白拿一个**集成冒烟测试**：仿真里 `rgbd_camera` 对着贴了二维码纹理的货架 → 看 `/qr` 有没有正确输出。
**但只用来测"管道通不通"，不要用它调解码精度**（见 §2.1 的保真度问题）。

## 3. 建议的执行顺序

```text
W1  T0 mock 节点 ──────────► M5 状态机可以先跑（不依赖任何硬件）
W1  M3 离线图像测试集 ─────► 手机采集即可开始（不等相机、不等整车）
W2  T1 bag 回放 ───────────► 真机录 1 次 /scan+/odom+/imu/data，离线调 Nav2
W2  T2 Gazebo（M4 主责）───► mecanum 模板 URDF → 场地世界 → 闭环练全流程
W3+ 真机联调（主场）───────► 仿真只在"进不了场地"时顶上
```

## 4. 决策清单（更新 D4）

| # | 决策 | 结论 | 说明 |
|---|---|---|---|
| **D4** | M4 是否启用仿真 | **是，但复用 linorobot2 的 Gazebo Harmonic 栈** | 不做自建仿真；上限 2 人日 |
| **D4a** | 仿真跑在哪 | **Ubuntu 24.04 PC/VM**（**不在树莓派上**） | 装 `ros-jazzy-ros-gz` |
| **D4b** | 仿真域名 | `ROS_DOMAIN_ID=197` | 与真机 42 隔离，避免 `use_sim_time` 冲突 |
| **D4c** | 仿真是否等 M1 的 CAD | **不等** | 先用 linorobot2 `mecanum` 模板 URDF，后替换 |
| **D8** | M3 是否做仿真 | **不做** | 改为**离线图像/视频回放测试集** |
| **D9** | T0/T1 是否必做 | **必做** | mock 节点 + bag 回放，成本极低、收益最高 |

---

## 5. 一句话总结

- **M4**：有必要——**但必须用 linorobot2 现成的 Gazebo Harmonic 栈**（自带麦轮模型、`MecanumDrive` 插件、还能把我们的 SLAM 地图转成仿真世界）。自建仿真则不划算。
- **M3**：没必要——**改成"手机拍难例 + 离线回放评测"**，更真实、更便宜、可重复。
- **两者都不能替代真机**：仿真/离线手段的定位是"**进不了场地时不让进度停摆**"，真机调试永远是主场。
