# 单模块测试说明

**做完一个模块就能先测，不用等整车。** 每个模块都在不启动状态机的情况下独立验收。

两个终端都要先：

```bash
source /opt/ros/jazzy/setup.bash
source ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=42
```

---

## M2 · 固件 / 底盘

```bash
# 看里程计
ros2 topic echo /odom

# 直行 1m / 原地转 360°，量误差
ros2 topic pub -r 20 /cmd_vel geometry_msgs/msg/Twist '{linear: {x: 0.15}}'
# 记录实际走了多远，误差应 < 3%

# 举升 / 放下
ros2 topic pub --once /lifter std_msgs/msg/UInt8 '{data: 1}'
ros2 topic pub --once /lifter std_msgs/msg/UInt8 '{data: 0}'
```

**验收**：4 轮方向正确、直行误差 < 3%、转角误差 < 5°、断流 0.5s 内停车、舵机举升不卡不烫。

## M3 · 感知 / QR

```bash
# ① 先离线验证「取流 + 解码」——不需要 ROS，也不需要整车
python3 tools/qr_preview.py       # 应弹出预览并框出二维码，打印识别文本

# ② 接上 ROS 后再验证话题
ros2 topic echo /qr
```

**顺序很重要**：先把**纯 Python 核心**用图片/视频回放调通（这一步不依赖 ROS，也不依赖硬件），再接薄封装。
这样解码算法出问题时，你能确定不是 ROS 或相机环境的问题。

依次把 `START`、`RACKA_xxxx`、`RACKB_xxxx`、`RACKC_xxxx`、`RACKD_xxxx`、`END` 举到相机前：

**验收**：6 类全部输出正确字符串、连续帧只发一次、无码时不崩不发错误内容、**每种截图存档**。

## M4 · 雷达 / 定位 / 导航

```bash
ros2 topic hz /scan
ros2 topic echo /scan --once
ros2 topic echo /imu/data --once     # 转动车体，角速度 z 应跟着变

# 定位是否收敛（RViz 里看粒子云）
rviz2

# 给一个已知点，看能不能到
ros2 topic pub --once /goal_pose geometry_msgs/msg/PoseStamped \
  '{header: {frame_id: map}, pose: {position: {x: 1.0, y: 0.5}}}'
```

**验收**：`/scan` 帧率稳定；定位跳变 < 3cm；给定 5 个已知点各 10 次，到达 ±5cm、撞墙 0 次。

---

## M5 · 状态机

```bash
ros2 run mission_control mission_node
```

另开终端手动喂数据，验证流程是否推进：

```bash
ros2 topic pub --once /qr std_msgs/msg/String '{data: START}'    # 应开始计时
ros2 topic pub --once /qr std_msgs/msg/String '{data: RACKA_4X6M}'
# 观察 /lifter、/cmd_vel 是否按流程发出
```

**验收**：喂 `START` 后开始计时；每步有超时且不卡死；喂错码不影响；3 分钟自动停。

## 通用验收记录格式

每次测试在 `tests/` 下追加一行：

| 日期 | 模块 | 测试项 | 结果 | 证据 | 测试人 |
|---|---|---|---|---|---|
| 2026-11-05 | M3 | 6 类 QR 识别 | 6/6 通过 | `tests/qr_shots/` | M3 |

**没有证据（截图/日志/bag）的测试等于没测。**
