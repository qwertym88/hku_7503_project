## IMU 交接给 M4 的限制

`/imu/data` 为 best effort，`frame_id=imu_link`；角速度 rad/s，加速度 m/s²，包含重力。只发六轴测量，`orientation_covariance[0]=-1` 表示无姿态估计；角速度/加速度协方差全 0 表示未知。原始 `/odom` 不融合 IMU。

静止陀螺均值 XYZ 为 `[-0.01375085, -0.00506584, +0.02455367] rad/s`，**仅测量，尚未在固件扣除**。Z 零偏若直接积分约产生 84.4°/分钟假转角，不能当作已校准航向。补偿后还需重复静置、重启/温漂及转向复测；单次静置加速度不能区分安装倾斜与加速度偏置。

用户确认 X 朝前、Y 朝左；平放 Z 约 +9.82 是向上支撑比力，与正 Z 朝上相符，无需单独反转 Z。精确安装角度、三轴旋转正负仍未独立验收，URDF 中的安装外参不能据此直接盖章。

平放窗口的消息年龄均值 93.8ms；另一手动姿态窗口出现约 -116～253ms，时间同步/主机时钟变化原因待查。诊断 `imu_age_ms` 约 2～4ms 仅表示 MCU 本地样本新鲜度，不等于主机端时间戳年龄。IMU 断流时停止发布旧数据，但当前固件**不会仅因 IMU 失效禁止速度命令**；M4/M5 的反馈失效停车仍需实现验证。

旧 `robot_navigation/config/ekf.yaml` 仍使用 `odom/unfiltered`，旧 launch 还存在将滤波输出改回 `/odom` 的接线。M4 应按[接口契约](模块接口说明.md)改为原始 `/odom` → EKF → `/odometry/filtered`，仅 EKF 发 `odom→base_footprint`；该接线和实车联合运行尚未完成。

## 接下来的执行顺序

1. **更换 M4 并复查四轮。** 正常闭环没有编码器失效自动停机，M4 无反馈会使 PID 持续加大输出。更换前保持 M4 断开，不运行整车闭环验收。新电机先逐轮检查一整圈计数与正反符号；独立开环工具见[单轮测试固件](../../firmware/motor_test/README.md)，临时使用后恢复正常固件并记录新哈希。
2. **架空验方向与停车。** 四轮按低速前进、后退、逆/顺时针原地转，核对实际方向、计数符号和反馈。随后测停止发布速度、结束 agent、拔 USB；从最后有效命令到轮子实际停止应 ≤0.5s，记录视频与日志。不能用 `enabled=0` 或计数停止代替物理停车证据。
3. **并行完成 IMU 与升降。** IMU 先做受控独立倾斜/旋转和静态零偏补偿复测，复查主机时间戳；升降先与 M1 冻结引脚、供电、行程、等待/异常策略，再实现 `/lifter` 并做 20 次真实载荷循环。物理急停与复位恢复行为也需在落地联合运行前验收。
4. **落地空载，再带载标定。** 先确认每转计数，再标轮周长，最后标旋转系数；按[里程计标定](里程计标定.md)操作。每种载荷下，前后 1m、前后 0.10m、±90°/±180°每种至少 5 次。目标：1m 误差 ≤3%，0.10m ≤1cm，转角 ≤3°；机械取放容差更严格时从严。
5. **完成供电、手动取放与联合交付。** 记录空/带载至少 3 分钟无重启及电池状态，手动取放一次；让另一位队友按说明从干净终端构建/启动。M4/M5 接真实 odom/IMU/雷达/EKF，验证反馈失效停车、单一速度发布者与急停后不自动续跑，再进入整车 C09～C16 验收。

M4 更换前可完成 IMU、升降与部署文档；缺轮反馈时，整车里程计精度、转向精度和载荷测试保持待测。
