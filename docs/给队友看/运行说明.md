# 固定路线方案运行与交接

更新于 2026-11-24。环境为 Ubuntu 24.04、ROS 2 Jazzy、树莓派 5 经 USB 串口连接 ESP32。标准场地的真机启动、任务开始、取消及复位命令见[标准场地固定路线真机运行](固定路线真机运行.md)。

## 已有工作区构建

Gazebo 的 ABCD 到位拍照、运动学搬运和 YAML 参数见[固定路线仿真使用说明](固定路线仿真使用说明.md)。

从仓库根目录，使用bash终端：

```bash
source /opt/ros/jazzy/setup.bash
cd ros2_ws
colcon build --symlink-install
source install/setup.bash
export ROS_DOMAIN_ID=42
```

每个新终端先加载 `/opt/ros/jazzy/setup.bash` 和工作区 `install/setup.bash`。zsh 使用对应的 `setup.zsh`。跨机调试需启用跨主机发现。

## 固定路线启动顺序

1. M1/M3按冻结起点复摆，确认货架、放置位、地面与路线版本一致；M2确认供电/急停、举升处于已确认低位。
2. M2启动micro-ROS agent和固件，检查原始/odom、/imu/data及时间戳，并确认固件不重复发布EKF负责的局部TF。本机已验证串口 `/dev/ttyUSB0`、921600、domain42；使用下方 Docker 命令，或已安装时运行 `ros2 run micro_ros_agent micro_ros_agent serial --dev /dev/ttyUSB0 -b 921600`。Pi 固定设备名和桥接包启动脚本仍待实现。
3. 运行 `ros2 launch robot_navigation fixed_route_hardware.launch.py`，加载标准场地地图，检查雷达、EKF、AMCL 与当前场地位姿。确认 `/cmd_vel` 由任务独占。
4. 人工调用 `/mission/start`。结束或故障后任务发送零速并保留举升控制。再次执行前复摆后调用 `/mission/reset`。

## 已验证的本机底盘操作

从仓库根目录构建：`bash firmware/chassis/idf.sh build`；烧录步骤见[固件说明](../../firmware/chassis/README.md)。当前正常应用已包含 IMU，不需为了观察接口重复烧录。新 M4 已更换待复测，先确认架空及反馈；整车运动与精度验收未通过。

同一串口只保留一个 agent，在本机已有 Docker 镜像时运行：

```bash
docker run --rm --name hku-chassis-agent --network host --device /dev/ttyUSB0 \
  -e ROS_DOMAIN_ID=42 microros/micro-ros-agent:jazzy \
  serial --dev /dev/ttyUSB0 -b 921600 -v4
```

已有容器则用 `docker logs -f --tail 30 hku-chassis-agent` 查看，`docker stop hku-chassis-agent` 停止；退出日志不停止后台容器。`--rm` 容器停止后需重建。复连异常先排除串口占用，再重建 agent 并按板上 RESET；固件没有自动断线恢复。完整状态、IMU 零偏/时间戳限制及验收顺序见[M2清单](M2底盘进度与交付清单.md)。

## 已有接口观察

先完成上面的环境source和agent启动：

```bash
ros2 topic echo /odom --once
ros2 topic echo /imu/data --qos-reliability best_effort --once
ros2 topic echo /odometry/filtered --once
ros2 run tf2_ros tf2_echo map base_footprint
ros2 topic hz /odom
ros2 topic info /cmd_vel -v
```

应有新鲜反馈、正确frame和唯一速度发布者。原始/odom输入EKF，EKF输出/odometry/filtered和局部TF；固定路段使用滤波局部反馈。不上relay，不将EKF输出映射回/odom。tf2_echo须定位模式就绪后运行。

## 记录证据

自动运行前另开终端，先source环境，再录制（ROS2 bag为标准命令，需本机具备rosbag2）：

```bash
ros2 bag record -o /tmp/fixed_route_run /odom /odometry/filtered /imu/data /scan /amcl_pose /tf /tf_static /cmd_vel /lifter
```

执行模式中/scan、滤波局部反馈与地图定位均必需；建图时AMCL不运行，另存建图bag。正式地图.yaml/.pgm独立保存；录包时核实静态TF已被捕获。/tmp/fixed_route_run每次换唯一名称，运行后及时复制到共享存储；bag不自动代替状态机日志与外部测量。所有结果按[验收协议](../../tests/保守方案验收.md)归档。

## M2简单地面运动（用户初步验证有效）

用户已反馈下列测试方案初步有效，尚无实测距离/转角/停车时延。当前固件采用左右轮组模型，拒绝非零linear.y；“向右0.2m”采用右转约90°后前进，完成后车头朝右。该命令组是速度定时粗测，不是距离/角度闭环。

在已source ROS、domain42、唯一agent运行且场地留出净空的条件下，每段单独执行，观察正常再继续。以下使用zsh：

```bash
source /opt/ros/jazzy/setup.zsh
export ROS_DOMAIN_ID=42
```

先前进约0.3m（0.05m/s，约6秒）：

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.05}, angular: {z: 0.0}}' \
  --rate 20 --times 120 --keep-alive 0 \
  --wait-matching-subscriptions 1 --max-wait-time-secs 5
```

每段结束都主动停车，后两段同样执行此命令：

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist '{}' \
  --rate 20 --times 5 --keep-alive 0
```

再原地右转约90°（-0.20rad/s，约7.85秒）；停车并观察车头方向再继续：

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.0}, angular: {z: -0.20}}' \
  --rate 20 --times 157 --keep-alive 0 \
  --wait-matching-subscriptions 1 --max-wait-time-secs 5
```

最后朝新的车头方向前进约0.2m（0.05m/s，约4秒），结束后再次执行上面的零速命令：

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.05}, angular: {z: 0.0}}' \
  --rate 20 --times 80 --keep-alive 0 \
  --wait-matching-subscriptions 1 --max-wait-time-secs 5
```

启动/停机和麦轮打滑会影响实际结果。每步尺量距离/地面角标读角度后再调参数，不以速度×时间证明精度。该主动停车测试也不代替480ms看门狗的物理停车验收。反馈与限制见[运动恢复记录](../../tests/firmware/2026-11-19_motion_recovered.md)。

## M2停车逻辑更新

按用户要求，源码已移除300ms无反馈和反向反馈的四轮停车锁存，未提交的1秒启动宽限也已撤销；用户已确认移除后可以控制小车移动；逐方向、精度与停车仍待量测。保留480ms速度命令超时、显式零速停车、通信故障处理和升降互锁。诊断用 `feedback_guard_enabled=false`、`lift_inhibited`替代旧mask字段。异常轮反馈不再自动停车，操作/验证见[移除记录](../../tests/firmware/2026-11-19_feedback_guard_removed.md)。

## M2编码器方向修订

用户已纠正轮ID接线，确认四轮向前滚动时原始 `counts` 均增加。固件已参考最近提交 `4943022` 撤销四轮反馈取反，恢复原始增量直接用于PID/里程计；前进时 `counts`增量、`speed`与`target`均为正。IMU校准、位置舵机、480ms看门狗与升降互锁保留。用户已确认当前基本移动恢复，修订历史见[恢复记录](../../tests/firmware/2026-11-19_encoder_baseline_restore.md)。

## M2 IMU校准状态与下一步

2026-11-19已完成静态陀螺零偏标定、板端补偿启用及补偿后静态复测。XYZ补偿值为 `[-0.0119512194,-0.0046553588,+0.0230571526] rad/s`；Z静态均值从1.32108°/s降至0.03825°/s（约降低97.1%）。当前IMU47.985Hz、odom20.001Hz；IMU约48Hz节拍仍需复查，未标为严格达到50Hz。见[校准完成记录](../../tests/firmware/2026-11-19_imu_calibration.md)。

当前 `imu_bias_enabled=1`，不用重复采集原始零偏，手动三轴旋转符号已由用户确认正常；断电重启、静置预热约60秒后可做一次只读重复性采集：

```bash
/usr/bin/python3 tools/chassis_imu_probe.py \
  --duration 65 --warmup 5 --label stationary_restart \
  --output "/tmp/imu_restart_$(date +%Y%m%d_%H%M%S).json"
```

仅观察残余均值、噪声/前后半段稳定性、时间戳和健康状态，不把已补偿数据交给原始校准器。当前小车基本移动、升降基本功能均已由用户确认，接着按[交付清单](M2底盘进度与交付清单.md)推进：先测物理停车/急停，补每圈计数与四方向记录，再做地面里程计标定、升降载荷20循环与供电，最后接EKF及M4/M5联合交付。现场确认范围见[基本移动恢复记录](../../tests/firmware/2026-11-19_motion_recovered.md)。

## M2升降（180°位置舵机）

位置控制新版已在本次IMU记录中确认运行；端点/载荷运动尚未验收。在底盘停稳且通信正常时，直接发送：

```bash
# 上升至menuconfig配置的最高角度，默认80°；等待结束后持续保持
ros2 topic pub /lifter std_msgs/msg/UInt8 '{data: 1}' --once
# 等实际停稳后下降至最低角度，默认0°
ros2 topic pub /lifter std_msgs/msg/UInt8 '{data: 0}' --once
```

当前本地sdkconfig/移除锁存版构建为下0°/上80°、等待各600ms；早先IMU采集会话的0°/75°、1200ms保留为历史配置。现场以实际diagnostics为准。无需arm，旧arm/jog服务已移除。`Chassis lifter (180-degree position servo)`菜单的LOWER_DEG/UPPER_DEG设置角度，UP_MS/DOWN_MS仅为稳定等待。首次命令前无PWM位置输出，stop撤销PWM、不能保证中间位置保持。端点标定、停止/恢复与烧录见[升降说明](../../firmware/chassis/LIFTER.md)。
