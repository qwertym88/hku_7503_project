# 里程计标定（M2 必读）

> 结论先行：**`COUNTS_PER_REV = 1040`（每转一圈轮子 1040 个计数），不是 260。**
> 依据：Yahboom 官方教程 `02. ESP32 basic course/08. Read motor encoder data.pdf` 原文。

---

## 1. 推导：1040 是怎么来的

官方原文（逐字引用）：

> "the motor reduction ratio is **1:20**, the encoder is a **13-line AB phase Hall encoder**, and the software uses **high and low level triggering at the same time**, so the theoretical number of pulses for one revolution of the motor should be **1040**."

拆开算：

| 项 | 值 | 说明 |
|---|---|---|
| 编码器线数（PPR） | **13** | 每转 13 个脉冲/相 |
| AB 双相 + 高低电平同时触发 | **×4** | 即正交解码 4 倍频（ESP-IDF 的 **PCNT** 外设，high+low 触发） |
| 减速比 | **×20** | 1:20 |
| **合计** | **13 × 4 × 20 = 1040** | 输出轴（轮子）转 1 圈的计数 |

官方还给了实测验证：

> "when the wheel turns **forward for one turn**, the encoder data increases by **approximately 1040**" / 反转一圈则减少约 1040。

> 注：原文写的是 "one revolution of the **motor**"，但紧接着的实测句说的是 "the **wheel** turns for one turn" → **1040 对应"轮子（输出轴）转一圈"**，这才是里程计要用的常量。

---

## 2. 为什么 260 是错的

**260 = 13 × 20**，等于**只数单相、不上 4 倍频**。

官方固件用的是 **PCNT 高低电平同时触发**＝4 倍频，所以如果按 260 去算里程：

- 每个计数对应的距离会被算成真实的 **4 倍**；
- 表现就是"车只走了 1m，里程计报告走了 4m"，导航/建图直接报废。

**记法：1104 里藏 4。** 260（×1）→ 1040（×4）。

---

## 3. 数值速查（65mm 麦轮）

| 量 | 公式 | 值 |
|---|---|---|
| 轮周长 | π × 0.065 | **0.20420 m** |
| 每计数距离（**1040**） | 0.20420 / 1040 | **0.1964 mm** |
| 每米计数 | 1040 / 0.20420 | **≈ 5093 counts/m** |
| ❌ 若误用 260 | 0.20420 / 260 | 0.7854 mm（**4 倍**） |
| ❌ 若误用 260 | 260 / 0.20420 | ≈ 1273 counts/m |

**M2 先按 1040 填，再用 §4 的标定把它微调到实测值。**

---

## 4. 三步标定（官方工具链）

Yahboom 提供两个标定工具，参数在 `rqt` 里改：

### 步骤 1：常量与轮径
先确认固件里的：
- `MOTOR_ENCODER_CIRCLE`（每圈计数）= **1040**
- `MOTOR_WHEEL_CIRCLE`（轮周长）= π × 实测直径
- `MOTOR_PID_PERIOD` = 0.01 s（10ms）

速度换算公式（来自官方 PID 教程，可直接抄）：

```c
// 目标速度 → 每 10ms 的编码器目标数
speed_count[i] = speed_m[i] / (MOTOR_WHEEL_CIRCLE / MOTOR_ENCODER_CIRCLE / MOTOR_PID_PERIOD);
// 每 10ms 实测数 → 实际速度
read_speed[i] = real_pulse[i] * (MOTOR_WHEEL_CIRCLE / MOTOR_ENCODER_CIRCLE / MOTOR_PID_PERIOD);
```

> 注意 `MOTOR_PID_PERIOD` 在这里被当成"秒"参与除法，**量纲要自己复核一遍**，别照抄错。

### 步骤 2：线速度标定 → `odom_linear_scale_correction`
- 让车**直行实测 1 m**（工具参数 `test_distance`）。
- 若里程计报告的 ≠ 1m，就改 `odom_linear_scale_correction`（源码里 `distance *= odom_linear_scale_correction`）。
- 轮子受压后的**实际滚动半径**与标称 65mm 有偏差，就靠这一步补。

### 步骤 3：角速度标定 → `odom_angular_scale_correction`
- 让车**原地转**，比较里程计的转角与实际转角。
- 修正 `odom_angular_scale_correction`（源码里 `delta_angle = odom_angular_scale_correction * ...`）。
- **麦轮当差速跑时辊子会侧滑，yaw 误差比普通轮更大，这一步必须做。**

## 5. 上电前检查清单（比常量更容易翻车）

| # | 检查 | 正确状态 |
|---|---|---|
| 1 | 四轮 ID 映射 | 左前=**Motor1**、左后=**Motor2**、右前=**Motor3**、右后=**Motor4** |
| 2 | 轮子"左旋/右旋"配对 | 装错会导致平移方向相反（我们保底不用横移，但会影响自转） |
| 3 | 电机线方向 | 白接头→控制板、黑接头→电机，**接反烧板** |
| 4 | 前进时四轮计数 | **都增加**（不是有的加有的减） |
| 5 | 原地转时 | 左侧与右侧计数**符号相反** |
| 6 | `MOTORx_INV` / `ENCODERx_INV` | 与实测方向一致 |
| 7 | 车体坐标系 | `+x` 车头、`+y` 车左、逆时针为正 |

## 6. 症状 → 病因对照

| 症状 | 最可能原因 |
|---|---|
| 里程计距离**恰好 4 倍** | 用了 260 而不是 1040 |
| 里程计距离差 5–15% | 滚动半径/打滑 → 线速度标定 |
| 直行时航向缓慢偏 | 左右轮径不一致 / 打滑 → 角速度标定 |
| 原地转角度差很多 | `LR_WHEELS_DISTANCE`（轮距）填错，或未做角速度标定 |
| 前进时里程计**倒退** | `MOTORx_INV` 或编码器 A/B 反接 |
| 位置对但方向反 | `base_footprint` 的 `+x` 定义与固件不一致 |
