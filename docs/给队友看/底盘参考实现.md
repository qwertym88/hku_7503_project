# 麦轮底盘参考实现（M2 必读）

> 目的：**不要自己推逆运动学**。麦轮是极成熟的配置，下面这些库/例程可以直接抄或改。
> 结论放在最前面，证据和链接在下面，可直接点开核对。

---

## 1. 结论：三条路，按优先级选

| 优先级 | 方案 | 为什么 |
|---|---|---|
| **① 首选** | **Yahboom 官方 micro-ROS 例程**（`twist_subscriber` + `odom_publisher`） | 和我们的板子、电机**完全同款**；已做好"订阅 `/cmd_vel` → 四轮 → 发 odom"。⚠️ **官方参考车是普通轮 4WD 差速，不含麦轮逆解**（见 §3.1） |
| **② 备选/互补** | **linorobot2_hardware** 的 `kinematics` 库 | Arduino/PlatformIO，**ESP32-S3 配置现成**，`MECANUM` 是枚举里的一档；PID、编码器、里程计结构都能抄 |
| **③ 不推荐（现阶段）** | `ros2_control` 的 `mecanum_drive_controller` | 确实存在且 Jazzy 已发布，但需要写 ros2_control 硬件接口，**对 5 人保底团队过重** |

**一句话**：用 ①，缺哪块从 ② 里抄，别碰 ③。

> ⚠️ **重要前提**：① 官方例程的底盘模型是**四轮差速（普通轮，不能横移）**，`V_y` 被忽略；
> **麦轮逆运动学只有 ② 有**。也就是说：**想开横移才需要 ②**，否则 ① 就够。详见 §3.1。

## 3. 首选：Yahboom 官方例程（同板同电机）

官方教程里已经有两个直接对应的例程：

| 例程 | 路径（官方虚拟机内） | 功能 |
|---|---|---|
| `twist_subscriber` | `~/esp/Samples/microros_samples/twist_subscriber` | **订阅 `/cmd_vel` → 驱动四轮** |
| `odom_publisher` | `~/esp/Samples/microros_samples/odom_publisher` | 在上一例程基础上**发布里程计** |

官方文档里的关键事实（已从教程 PDF 核对）：

- 板子芯片是 **ESP32-S3-WROOM**，开发框架是 **ESP-IDF**（不是 Arduino）。
- 四轮接口定义固定：**左前→Motor1、左后→Motor2、右前→Motor3、右后→Motor4**。
- 编码器接口：`M1+/M1-` 电机，`GND/VCC` 编码器供电，`H1A/H1B` 编码器脉冲。
- 初始化调用 `Motor_Init`，官方已封装好 **310 编码电机组件**，拷进工程即可用。
- 出厂固件**只提供 bin，不提供源码**。

> ⚠️ **首要待办（M2 第 1 天就该问）**：拿到 Yahboom 资料包/虚拟机，确认 `microros_samples` 源码在不在里面。**在 → 直接改，M2 工作量减半。**

### 3.1 官方参考车用的是"普通轮"，不是麦轮（已逐篇核实）

我把官方仓库**全部 67 个教程 PDF** 提取为文本并全文检索，结论明确：

| 证据 | 出处（官方仓库内） | 原文 |
|---|---|---|
| 明确说是**普通轮胎**、**不能横移** | `05. Robot basic course/2. Robot keyboard control.pdf` | "the car has a four-wheel drive structure with **ordinary tires** and **cannot move sideways**, the [t] button has no meaning" |
| 模型是**左右两组**差速，无横移项 | `02. ESP32 basic course/16. Robot kinematics analysis.pdf` | `V_m1 = V_m2 = V_x − V_z·(A+B)`；`V_m3 = V_m4 = V_x + V_z·(A+B)` |
| 明说 **V_y 无效** | 同上 | "V_x represents the control linear velocity…, **V_y is invalid**, and V_z represents…"；代码 `car->Vy = 0;` |
| 订阅回调把 **y 写死为 0** | `03. microros basic course/06. Subscribe speed control topics.pdf` | `Motion_Ctrl(twist_msg.linear.x, `**`0`**`, twist_msg.angular.z);` |

**所以：官方例程 = 四轮差速／滑移转向（skid-steer）模型，`Motion_Ctrl` 的 `V_y` 形参存在但被忽略。**

> 补充：官方标定工具里的 `direction` 参数注释为"可用于轮式结构小车校准左右移动的线速度"——说明**工具链兼容麦轮机型**，但**这套教程的参考车并非麦轮**。

**对我们（课程发的 65mm 麦轮）的意义：**

- ✅ **保底路线零冲突**：我们本来就建议"先当四驱用、不开横移"，官方例程正是这个模型，**可以直接照搬**。
- ❌ **想要麦轮横移，官方给不了**：`linear.y` 被丢弃，必须换 ② linorobot2 的麦轮逆解；且导航侧要能输出 `linear.y`（Nav2 默认差分控制器不给）。
- ⚠️ **必须标定**：官方提供"线速度标定 / 角速度标定"工具和 `odom_linear_scale_correction`。**麦轮底盘当差速跑时打滑更大**，yaw 比例与线速度系数要实测校准。
- 🔎 **底盘物理上仍是麦轮**，只是被当四驱驱动——轮子的辊子会有额外打滑，里程计精度会比普通轮差，**这更说明定位要依赖雷达**。

## 4. 备选：linorobot2_hardware 的 kinematics 库

如果官方例程拿不到，或想换 Arduino 生态，这个库可以直接抄公式和结构。

**逆运动学（麦轮）**——`firmware/lib/kinematics/kinematics.cpp` `calculateRPM()`：

```cpp
float tangential_vel = angular_z * (wheels_y_distance_ / 2.0);
float x_rpm  = (linear_x * 60.0) / wheel_circumference_;
float y_rpm  = (linear_y * 60.0) / wheel_circumference_;
float tan_rpm = (tangential_vel * 60.0) / wheel_circumference_;
// 四轮 = x ± y ± tan 的组合，并带"超过电机最大转速就等比缩放"的保护
```

**正运动学（odom）**——`getVelocities()`：

```cpp
average_rps_x = (rpm1 + rpm2 + rpm3 + rpm4) / 4 / 60.0;   // 前进
average_rps_y = (-rpm1 + rpm2 + rpm3 - rpm4) / 4 / 60.0;  // 平移（仅 MECANUM）
average_rps_a = (-rpm1 + rpm2 - rpm3 + rpm4) / 4 / 60.0;  // 旋转
```

它还自带：
- `lib/encoder`、`lib/motor`、`lib/battery`、`lib/wifi/ota`
- PID 参数模板 `K_P/K_I/K_D`、`COUNTS_PER_REV`、`WHEEL_DIAMETER`、`LR_WHEELS_DISTANCE`
- **`config/custom/esp32s3_config.h`**（同款芯片）、micro-ROS over **serial 或 wifi** 两种传输

> ⚠️ 差异点：它的电机驱动只支持"通用 2 路方向 + PWM"、"通用 1 路"、"BTS7960"、"ESC"。**Yahboom 板载的电机驱动不在其中**，电机层要自己适配（但运动学和 PID 可以直接用）。
> 另外它的 `LINO_BASE` 默认是 `DIFFERENTIAL_DRIVE`，用麦轮要把 `MECANUM` 那行的注释打开。

## 5. 上位机侧：`ros2_control`（Jazzy 已发布，但暂不用）

`ros2_controllers` 的 **`jazzy` 分支**里确实有：

- `mecanum_drive_controller/`（`mecanum_drive_controller.cpp` + `odometry.cpp`）
- `omni_wheel_drive_controller/`

用法：它在 Pi 上跑，通过 `hardware_interface` 收各轮速度指令、读各轮位置，**自己算麦轮运动学、发布 odom 与 TF**。

**为什么我们不选**：它要求你为 ESP32 写一个 ros2_control 硬件接口（还得在板子上按"每轮速度"通信），比"ESP32 直接收 Twist"多一层，且和我们的 5 话题契约冲突。**保底阶段不引入。**

## 6. micro-ROS Agent：确认可用（含串口）

- `micro-ROS/micro-ROS-Agent` **有 `jazzy` 分支**。
- 官方 README 明确支持 **UDP/TCP + Serial Port** 两种传输 → **满足需求文档"USB 串口通信"的要求**。
- 已知坑：Docker 里跑 agent 时串口偶发丢包；**建议源码编译，不用 snap**。

## 7. 一个必须定死的决策：运动学只放一侧

**不要两侧各算一次**（ESP32 算一遍、Pi 再算一遍 → 双重换算、方向混乱、难排查）。

按我们的 5 话题契约：

```
ESP32 收 /cmd_vel(Twist: vx, vy, ω) → [ESP32 做运动学 + PID] → 四轮
   ↑ 保底：四轮差速（忽略 vy，即官方例程的做法）   ↑ 要横移：麦轮逆解（抄 linorobot2）
ESP32 读编码器 → [ESP32 做正解 + 里程] → /odom（remap 为 odom/unfiltered）
ESP32 读板载 IMU(ICM42670P) → /imu/data
```

**结论：运动学全部放 ESP32 固件侧**，Pi 侧不装任何麦轮控制器。这条写进《模块接口说明》。

## 8. 保底建议：先别依赖"横向平移"

麦轮的价值是能横着走，但那要求**导航侧输出 `linear.y`**（Nav2 默认的差分控制器不会输出横向速度，要用 omni/mecanum 控制器）。

- **保底阶段**：把麦轮当普通四驱用（`linear.y = 0`），逆运动学退化成四轮差速，风险最低、调试最简单。
- **有余力再开**：等导航调通、时间富余，再启用横向平移做微调对准。

> 这样 M2 的第 1 周只需要证明"能前进/后退/自转"，不必纠结平移方向对不对。
