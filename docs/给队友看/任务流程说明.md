# 任务流程说明

一句话：**扫到起点码就自动开始，一个一个把货架搬到目的区，全程不碰墙。**

```text
待机
 → 相机看到 START（或任意 RACKx_xxxx 亦可启动，容错）
 → t0 = now，三分钟开始计时
 → 循环（按坐标从近到远）：
     ① 导航到"该货架前的固定停靠点"
     ② 等 /qr 出现对应的 RACKx_xxxx（超时 5s 就继续，不卡死）
     ③ 举升：/lifter = 1，等 2s
     ④ 导航到目的区固定停放点
     ⑤ 放下：/lifter = 0，等 2s
     ⑥ 还有货架且剩余时间够 → 回到 ①
 → 全部送完 或 3 分钟到 → 停车
```

**没有逐步人工确认。** 每一步由状态机下发，模块做完即返回，状态机直接进入下一步。

## 异常怎么处理（保底策略）

| 情况 | 处理 |
|---|---|
| 某货架扫码不到 | 等 5s 超时后**继续**，不原地卡死 |
| 某货架连续取 2 次失败 | **跳过**，先取下一个，保住完成数量 |
| 导航失败/超时 | 重试 1 次；仍失败则跳过该货架 |
| 举升超时 | 记录异常，继续流程（避免整轮卡住） |
| 撞墙风险 | 宁可慢，膨胀半径设大；撞墙 -2 分很亏 |
| 时间到 | 立刻停车，保留已送达记录 |

> 核心取舍：**先保证"送到的数量"，再追求"每个都完美"。**

## 计分提醒（来自需求 PDF）

- 每个货架成功进入目的区：**+5 分**
- 机器人或货架撞墙：**每次 -2 分**
- 运送途中**货架不得触地**
- 结束时统计目的区内货架数并参与全组排名

## 与需求文档的对应

- 起点码 `START`、终点码 `END`、货架码 `RACKA_XXXX`（XXXX 每队唯一）。
- **每个二维码的解码结果都要截图**，这是提交要求之一。
- 每轮流程必须能被相机/雷达/舵机真实执行；模拟通过不算完成。

*本说明是组内流程约定，最终计分以老师现场判定为准。*
