# 标准场地固定路线真机运行

树莓派直接从仓库安装 [field_geometry.pgm](../../sim/maps/field_geometry.pgm) 和 [field_geometry.yaml](../../sim/maps/field_geometry.yaml)。固定路线使用 `/odom` 的轮式里程计驱动 EKF，通过 `/odometry/filtered` 和局部 TF 向 AMCL 提供运动估计。AMCL 用 MS200 扫描与标准地图修正全局位姿，由 `map → odom → base_footprint` 获得车体坐标。固定路线启动时预先算好，运行中依据地图坐标闭环跟踪。

AMCL 地图包含场界和直径 6 cm 的 S、E 柱。任务按货架初摆、搬起与放下的顺序维护货架几何。路线对柱子与非对接货架使用 10 cm 净距，规划另预留 1.2 cm，正在对接的目标货架使用 5 mm 模型净空。C 架退出后，车直接驶到 D 架 +Y 侧的 `(0.410, 1.445)` m，朝 −Y 停稳扫码。随后前进 35 cm 进架，举升后后退 35 cm 回到同侧，再前往放置位。路线按初始摆位执行，现场临时移动货架后需要恢复摆位，或更新布局并重新启动规划。

## 树莓派启动与复位

首次更新时，在树莓派同步仓库并构建工作区。日常启动由脚本加载环境。

```bash
cd ~/hku_7503_project/ros2_ws
source /opt/ros/jazzy/setup.bash
colcon build --packages-up-to robot_navigation
```

把货架摆回初始坐标，把空载小车中心放在 `(1.0, 0.30)` m，车头朝 +Y，保持托叉下降范围畅通。从 SSH 登录后的任意目录执行下列命令。

```bash
~/hku_7503_project/tools/run_robot.sh
```

脚本启动或复用底盘 Agent 和任务服务，自动等待静止、解锁、按需要降叉，并在雷达、相机、里程计和 AMCL 就绪后启动任务。终端打印当前等待项及结果。底盘默认使用 `/dev/ttyUSB0`、921600、ROS 域 42，MS200 默认使用 `/dev/ttyACM0`。旧任务服务仍在运行时，升级后执行一次 `~/hku_7503_project/tools/run_robot.sh shutdown`，再启动新版。

每次开始任务时，启动流程将人工摆放的已知起点设为 AMCL 初值，通过新计算的 `map → odom` 将连续累计的底盘里程计对齐到地图。RViz 与任务控制器使用同一套地图定位。

| 同一个小车端脚本的参数 | 用途 |
| --- | --- |
| `reset` | 车辆与货架复摆后，自动解锁、降叉并清空任务状态。下一次启动才向 AMCL 设置初始位姿 |
| `stop` | 取消准备或任务并发送零速，固件维持举升控制 |
| `logs` | 实时查看任务与二维码日志 |
| `shutdown` | 关闭任务进程，供更新后重新加载代码或启动参数 |

任务作为树莓派用户服务在后台运行，用 `stop` 停车。如果任务仍在运行，先停车，再复摆并执行 `reset`。升降完成来自固件计时回执。目前车上没有实际高度反馈。

首次启动可附带 ROS 参数，例如 `~/hku_7503_project/tools/run_robot.sh start lidar_port:=/dev/ttyACM1`。用 `DASE_CHASSIS_PORT` 指定底盘串口，用 `DASE_ROS_SETUP` 指定已构建部署的环境文件。已有独立雷达或相机节点时可传 `launch_lidar:=false` 或 `launch_camera:=false`。雷达和相机外参可通过 `robot_urdf:=/绝对路径/实测外参.urdf` 切换，支持用 `camera_source:=picamera2` 切换相机实现和用 `focus_diopters:=数值` 锁定焦距。

## 纯编码器模式

小车和货架按标准场地复摆后，在小车端运行以下任一命令。首次使用需要构建上文所列的 ROS 包。

```bash
~/hku_7503_project/tools/run_robot_encoder.sh
~/hku_7503_project/tools/run_robot_encoder.sh stop
~/hku_7503_project/tools/run_robot_encoder.sh reset
~/hku_7503_project/tools/run_robot_encoder.sh logs
```

行驶使用预先生成的固定路线和底盘原始 `/odom`。每次启动都把当时的编码器位姿对齐到人工摆好的起点，底盘累计里程可以跨轮次保留。相机负责二维码，底盘诊断负责自动解锁和升降回执。日志目录为 `ros2_ws/runtime_logs/fixed_route_hardware_encoder/`。

两种模式共用一个任务服务。切换模式前用当前脚本执行 `shutdown`。纯编码器模式在 RViz 发布估计车位和路线，场景图层可通过 `/mission/scene_map` 查看。打滑和轮径偏差会随行驶积累，实际净距需通过场地测试验证。

## 在本机打开 RViz

电脑和树莓派接入同一可互通网络后，在电脑仓库中执行下列命令。

```bash
./tools/run_rviz.sh
```

脚本默认连接 `10.199.166.59`，小车换地址时把新 IP 作为参数传入。RViz 显示标准地图、MS200 扫描、AMCL 位姿、紫色完整路线和绿色当前路段。

目标二维码顺序为 `START`、A 到 D 架和 `END`。沿途读到下一个目标码即保存同一帧图像，`logs` 终端显示完整码值和 PNG 绝对路径。到扫码点后仍读不到目标码时，15 秒超时，记录 `photo_skipped` 并继续下一动作。

AMCL 模式每次运行在 `ros2_ws/runtime_logs/fixed_route_hardware/` 下创建独立目录，保存定版路线、事件和成功扫码的 PNG。可用 `output_dir:=/绝对路径/tests/qr_shots` 把运行目录放到验收照片目录下。真机参数见 [fixed_route_hardware.yaml](../../ros2_ws/src/robot_navigation/config/fixed_route_hardware.yaml)，空载、带载、进架速度上限分别为 0.20、0.16、0.09 m/s。10 cm 是几何检查值，实际净距取决于定位、外参与机械包络。
