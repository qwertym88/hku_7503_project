# 标准场地固定路线真机运行

树莓派直接从仓库安装 [field_geometry.pgm](../../sim/maps/field_geometry.pgm) 和 [field_geometry.yaml](../../sim/maps/field_geometry.yaml)。AMCL 使用 MS200 雷达与 EKF 的局部里程计定位，最终由 `map → odom → base_footprint` 获得车体在标准场地里的坐标。原始 `/odom` 和 `/imu/data` 输入 EKF，融合结果发到 `/odometry/filtered`。固定路线启动时预先算好，运行中依据地图坐标闭环跟踪。

AMCL 地图包含场界、S 柱和 E 柱。任务按货架初摆、搬起与放下的顺序维护货架几何。路线对柱子与非对接货架使用 10 cm 净距，规划另预留 1.2 cm，正在对接的目标货架使用 5 mm 模型净空。D 架拍照时车中心在 `(0.410, 0.895)` m，位于 D 架的 −Y 侧，朝 +Y 停稳拍照，再向 +Y 前进 20 cm 进架。路线按初始摆位执行，现场临时移动货架后需要恢复摆位，或更新布局并重新启动规划。

## 树莓派启动

同步完整仓库，包含 `sim/maps/`。在仓库根目录打开 zsh，构建新版工作区。bash 使用相应的 `setup.bash`。

```zsh
source /opt/ros/jazzy/setup.zsh
cd ros2_ws
colcon build --packages-up-to robot_navigation
source install/setup.zsh
export ROS_DOMAIN_ID=42
```

启动 micro-ROS agent，沿用现有配置 `/dev/ttyUSB0`、921600、域 42。同一串口运行一个 agent。Docker 方式和底盘连接步骤见[运行说明](运行说明.md#已验证的本机底盘操作)。

把货架摆回各自初始坐标，把车中心放在 `(1.0, 0.30)` m，车头朝 +Y。空载时将举升机构置于低位。固件重启后举升位置为未知，使用自己的域 42 终端，在车停稳且任务尚未启动时发一次下降指令。等待诊断显示 `lifter_state=idle` 和 `lifter_position=0`，同时目视确认实际低位。

```zsh
ros2 topic pub --once /lifter std_msgs/msg/UInt8 '{data: 0}'
ros2 topic echo /chassis/diagnostics std_msgs/msg/String --qos-reliability best_effort
```

在已加载工作区的终端启动任务。默认使用 `/dev/ttyACM0` 连接 MS200，`rpicam-vid` 采集图像。有图形桌面时加 `rviz:=true`。

```zsh
ros2 launch robot_navigation fixed_route_hardware.launch.py
```

`lidar_port:=/dev/…` 可指定实际雷达串口。`robot_urdf:=/绝对路径/实测外参.urdf` 可替换车体坐标描述，保留 `base_footprint`、`laser`、`imu_link`。仓库默认 URDF 的雷达和相机外参是示例，首次带载前应使用实测外参并用 RViz 检查点云与墙面对齐。需要 Picamera2 时用 `camera_source:=picamera2`，需要锁定焦距时设置 `focus_diopters:=数值`。已有独立雷达或相机节点时可用 `launch_lidar:=false` 或 `launch_camera:=false`；关闭雷达启动时由已有节点提供 `/scan` 和传感器静态 TF。

RViz 的固定坐标系为 `map`。紫色显示完整任务路线，绿色显示当前路段，地图、雷达和 AMCL 位姿可一起观察。启动日志还会打印 `route.yaml`、`route.svg` 及 `fixed_route.rviz` 的路径。可将 `fixed_route.rviz` 复制到处于同一 ROS 域的电脑上，用 `rviz2 -d` 打开。

## 启动、停车与复位

在第二个域 42 终端查看定位和任务状态。`state=IDLE` 且 `start_blocker=null` 表示软件启动检查通过。用 RViz 的 **2D Pose Estimate** 可在物理起点重新给 AMCL 初值。运行前预览轨迹，检查托叉和线缆包含在车体包络中，并确认 D 架拍照距离可对焦。

```zsh
ros2 run tf2_ros tf2_echo map base_footprint
ros2 topic echo /mission/status std_msgs/msg/String --qos-durability transient_local
ros2 service call /mission/start std_srvs/srv/Trigger '{}'
ros2 service call /mission/cancel std_srvs/srv/Trigger '{}'
```

先确认其他速度控制程序退出，使 `/cmd_vel` 由任务独占。任务结束、取消、定位或关键反馈失效时发送零速。取消保留固件的举升控制。复跑前人工恢复货架和车的起始位置、确认机构在低位，再调用 `/mission/reset`。固件的升降结束是按计时确认目标，实际机构高度需现场验收。

```zsh
ros2 service call /mission/reset std_srvs/srv/Trigger '{}'
```

每次运行在 `ros2_ws/runtime_logs/fixed_route_hardware/` 写入定版路线、事件与四张停稳后的 PNG。真机参数见 [fixed_route_hardware.yaml](../../ros2_ws/src/robot_navigation/config/fixed_route_hardware.yaml)，首版空载、带载、进架速度上限分别为 0.20、0.16、0.09 m/s。10 cm 是几何检查值，实车净距仍受定位精度、外参与机械包络影响。当前执行器跟踪固定路线，现场新增障碍的识别和绕行不属于这一执行流程。
