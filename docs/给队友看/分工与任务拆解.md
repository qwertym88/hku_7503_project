# 五人任务安排：固定路线与预编程状态机

执行基线 v2.1，2026-11-11。全员先读本文，再读[建图定位与固定路线方案](建图定位与固定路线方案.md)、[任务流程](任务流程说明.md)、[接口](模块接口说明.md)。真实雷达建图与实时定位是底线；在线规划和Nav2路径跟随为可选增强，QR不再作为任务推进门槛。

目标：固定摆车，按预先冻结的顺序逐个搬运货架；每个货架执行“到扫码停靠位→等待→前进 0.10m→举升→沿固定路线到专属放置位→放下→后退 0.10m→下一货架”。扫码停靠位沿用地标名称，等待结束按程序推进，不等待 QR 结果。路线包含从货架退出、带载转弯和放下后离开的全部路段。

路线不实时规划；直行距离与转向/保向使用经标定的局部反馈，时间仅用于等待与超时。雷达真实建图并在执行时实时定位；第一版地图定位用于显示、记录与健康检查，不直接介入每个0.10m动作，固定路线累计误差通过整轮实测控制。默认顺序 A→B→C→D；M3/M4 可在标定期间调整，冻结后不得临时重排或跳过。具体坐标和路线尚未测量。

原任务书要求扫码启动、货架扫码及雷达定位导航；本方案保留真实雷达建图/定位与固定路线自动取放，扫码门控仍有差异。M5记录教师对固定路线和扫码简化的确认结果；不能把可选的在线规划当作已实现，开发按本方案继续。依据：`requirements/1. DASE7503 Group Project_2026-27_1B.pdf` 第 2–3 页，QR 截图要求见需求 2 第 1 页。

## M1：机械与取放几何

主责：整车、举升与载荷几何。协作 M2、M3；依赖实物货架，不能只用图纸。

| 任务 | 交付与接收人 | 验收和证据 |
|---|---|---|
| M1-1 整车装配、供电安装和包络 | 实体车、尺寸表→M2/M4 | 收拢尺寸不超过 300×300×180mm；三向带尺照片，记录托叉/货架实际扫掠包络 |
| M1-2 举升机构与货架接口 | 舵机升降位置、最大行程、稳定时间→M2/M5 | 真实载荷连续 20 次升降，无遮挡卡死、无滑落；循环表和连续视频，记录离地间隙 |
| M1-3 驶入/退出几何 | 每架进入距离、放置后退出距离、容许横偏/角偏→M3/M4 | 从标定停靠位前进 0.10m 能到可举升位；放下后退 0.10m 可脱离。若实物不成立，实测改参数后冻结，不靠盲推 |
| M1-4 带载外形与净空 | 空载/带载宽长、转弯净空、传感器遮挡→M4 | 最窄通道与原地转向实测视频；货架全程离地、不扫墙 |
| M1-5 CAD 交付与备件 | SolidWorks pack-and-go、加工件→M5 | 他机打开总装；提交包、打开截图、易损件清单 |

暂停精细外壳美化、新举升方案、横移机构开发。M1 的取货允许偏差决定停靠验收，不能只套用 ±5cm。

## M2：底盘、固件与反馈

主责：ESP32、micro-ROS USB 串口、供电与执行。协作 M1/M4；沿用官方 ESP-IDF 例程，不更换框架。

2026-11-18进度：正常固件含 odom/IMU 已烧录，静态接口已测；用户确认 M1～M3 正常，M4 编码器待换。四轮闭环、标定、升降、安全/供电交付尚未通过。分项证据与后续顺序见[M2进度与交付清单](M2底盘进度与交付清单.md)。

| 任务 | 交付与接收人 | 验收和证据 |
|---|---|---|
| M2-1 轮序、电机 PID、前进/后退/原地转 | 固件与引脚/轮序表→M4 | 四轮方向正确，linear.y=0；轮序视频和版本号 |
| M2-2 原始 /odom、/imu/data | 标准消息、频率/时间戳/偏置记录→M4 | odom 建议≥20Hz、IMU建议≥50Hz；实际频率写证据；确认1040计数适用于当前编码方式，完成直行/转角标定 |
| M2-3 低速短行程与载荷标定 | 前后0.10m、1m、±90°/180°的空载/带载结果→M4 | 1m误差≤3%；0.10m误差≤1cm；转向误差≤3°，均为新验收目标、每种至少5次；尺/地面角标与逐次表 |
| M2-4 舵机控制 | /lifter=0/1、升降时间和异常处理→M5 | 配合M1完成20循环；等待时间据实测最大值加余量；重复命令幂等，不虚报到位反馈 |
| M2-5 看门狗、急停与断电处理 | 固件、物理急停、烧录说明→M5 | /cmd_vel断流0.5s内停车；USB断线/进程退出停车实测；急停释放或重启后不自动续跑；停车视频及日志 |
| M2-6 供电与手动兜底 | 空载/带载供电记录、键盘取放→M5 | 至少完整3分钟无掉电重启；手动取放一次；电池状态、视频、固件构建/烧录命令 |

主路中原始/odom由M2唯一发布，供EKF输入；EKF输出/odometry/filtered并唯一发布odom→base_footprint，M2关闭同一TF广播。不上relay，不将滤波输出改回/odom；M4据此接建图/定位与固定路线。

## M4：真实建图、实时定位与固定路段执行

主责为复用现有雷达/SLAM/EKF/AMCL链路并完成固定路线执行。协作M2/M3；先打通真实建图和定位，暂停厘米级定位调优、Nav2在线规划/路径跟随和Gazebo新投入。定位组件与规划控制组件分开启动。

| 任务 | 交付与接收人 | 验收和证据 |
|---|---|---|
| M4-0 建图与实时定位（必做） | 真实场地图、存图/重载命令、AMCL与RViz、唯一TF接线→M3/M5 | 先真移动采图再重载；实车平移/转向定位随动，整轮持续可用；按C14–C16验收，不强制厘米误差 |
| M4-1 运动原语 | robot_navigation中的直行、后退、转向、等待、停止实现→M5 | 反馈到达才完成，距离/角度/状态有日志；5次重复满足M2目标，支持空载/带载限速 |
| M4-2 坐标与航向约定 | 出生位姿、场地/地图/局部坐标关系、反馈与TF归属→M5 | 原始/odom输入EKF，/odometry/filtered用于局部执行；AMCL做地图定位；固定起点建立任务局部变换，不硬清零EKF，不混减坐标 |
| M4-3 编译完整路段序列 | 路线YAML、参数版本→M5 | 接收M3测量后形成唯一执行配置；出发、取货、带载、退出、转场全部有段号，缺参数拒绝启动 |
| M4-4 接近与带载动作 | 各架0.10m驶入、放置退出及速度档→M5 | 实际误差满足M1机械允许范围；0.10m动作低速，计入制动余量；无载荷滑移/触地 |
| M4-5 停车条件 | 传感器新鲜度、卡住/超时、取消与障碍检查→M5 | 局部反馈/scan失效或定位TF链不可用停车；不因普通定位波动/未达厘米精度拒跑；前后/旋转按外形检查，雷达遮挡不能判为安全 |
| M4-6 单段、整路及累计漂移 | 每段表与整轮终点误差→M3/M5 | 通行路段偏差不超实测净空预算，取货/退出点满足M1容差；地图定位误差记录但不设统一厘米门槛；空/带载及完整顺序都验证 |
| M4-7 交给mission的调用边界 | Python调用约定与可中断tick接口→M5 | 按[接口说明](模块接口说明.md)联调；单一速度发布者；现有waypoint_driver未经修正不能直接用作比赛程序 |

雷达建图、存图/重载和实时定位必须完成，不因固定路线而删除。近障停车另外验证，取货区按实际通道配置接近检查。先复用现有SLAM/EKF/AMCL，确保odom与TF单一发布；实时规划/重规划仅在主线通过后考虑。M4不承担动态发现货架。

| 任务 | 交付与接收人 | 验收和证据 |

| M5-2 固定取放流程 | 等待、0.10m驶入、升降、路线、0.10m退出→全员 | 按[任务流程](任务流程说明.md)执行；不靠二维码推进，不自动跳架；机械等待时间已实测 |
| M5-3 统一启动及互斥 | robot_bringup、micro-ROS agent、模式与停止入口→全员 | 统一支持建图/定位执行两模式；自动时map_server+AMCL+EKF与mission同跑，Nav2规划控制/旧waypoint/teleop不争用速度；重启回待命 |
| M5-4 180s计时与故障处理 | 单调时钟、每步超时、故障锁存→全员 | 截止即零速；带载时保持支撑，不盲目放下；故障停车后人工重新摆车复位；完整故障测试记录 |
| M5-5 单架与四架验收 | tests/保守方案验收.md与TEST_LOG→全员 | 先A连续5次，再固定四架连续5轮；每轮雷达与定位真实同跑、≤180s、0撞墙、运输不触地、四个放置位正确、无中途干预 |
| M5-6 评分口径与交付 | 教师确认记录、README、PPT、代码/CAD/证据包→全员 | 明确真实建图/定位+固定路线自动取放，扫码门控和在线规划未实现则如实注明；不把截图当比赛扫码；他机恢复启动，材料齐全 |

预编程主路不自动重试、跳架或带载续跑。故障从稳定停车开始处理，避免重复执行“前进0.10m”导致撞架。

## 证据与协作

验收步骤、字段、通过标准唯一来源为[保守方案验收](../../tests/保守方案验收.md)。每次测试由主责执行，M3独立量测，M5在TEST_LOG汇总；另一名队友能按命令复现才交付。每天联调15分钟：只报最近失败、当天交接和下次验收。

Git速查（仓库根目录）：`git status`检查改动；`git diff`审阅；`git add <文件>`；`git commit -m "说明"`。参数变化与证据绑定提交号。

ROS 2速查（先source环境）：`ros2 topic echo /odom --once`查反馈；`ros2 topic hz /odom`查频率；`ros2 topic info /cmd_vel -v`查发布者。
