# 雷达建图、实时定位与固定路线执行

执行基线v2.1，2026-11-11。适用M2/M3/M4/M5。目标是尽快完成真实的“雷达地图上可观察机器人位置，机器人按固定路线自动取放”。任务顺序与路径提前写好；建图和实时定位是必做，在线路径规划与Nav2自动导航是可选增强。

2026-11-21仿真进展：已有基于现有CAD小车/场地的ABCD固定路线状态机、到位拍照、运动学搬运及可校准YAML，操作见[固定路线仿真使用说明](固定路线仿真使用说明.md)。这是先验证流程的独立仿真入口；下文真实EKF/AMCL接线与实车联合验收要求保持有效，不能把仿真DONE计作实车通过。

## 最小交付范围

| 能力 | 优先级 | 成功的含义 |
|---|---|---|
| 真雷达扫描、建图与存图 | 必做 | 实际移动采集场地，生成可辨认墙体/通道的地图，保存并重载；桌面图不替代正式场地图 |
| 地图上的实时定位 | 必做 | 重载地图后初始化真实出生位姿；实车平移/转向时定位与扫描能跟随，在整轮中持续可用；不是固定点动画或mock里程计 |
| 固定路线自动取放 | 必做 | 程序按冻结顺序执行直行/后退/转向、等待和升降，完成对应货架 |
| 定位精度调优、路线自动规划与重规划 | 可选 | 主线实车验收通过后再投入；不要求先做到定位跳变<3cm或Nav2到点±5cm |
| QR控制任务推进、动态发现/择架、自动选放置位 | 本轮暂停 | 固定顺序与位置，沿用停靠等待；已有QR截图保留 |

固定路线的机械动作仍需停在可取放的位置；“不考核厘米级地图定位”不等于允许撞墙、插偏或举不到。地图定位功能与固定路段闭环分别验收，取放允许偏差由M1实测确定，路线偏差由净空决定。

## 两个运行模式

1. **建图模式**：真雷达、原始odom/IMU、EKF局部里程计TF、slam_toolbox；人工低速推行/遥控采图，固定路线mission关闭。优先以稳定墙体/边界作定位参照，确认覆盖、保存`.yaml/.pgm`后结束建图。不能仅靠零速mock证明移动建图。
2. **执行模式**：真雷达、原始odom/IMU、同一EKF、map_server+AMCL、固定路线mission、RViz。不启动slam_toolbox、Nav2 planner/controller或旧waypoint_driver。AMCL负责实时定位，固定路线执行器负责唯一速度输出。

复用现有slam_toolbox、EKF和Nav2中的定位组件。仓库已有slam.launch.py/navigation.launch.py与配置；本机已安装的`nav2_bringup/launch/localization_launch.py`可单独启动map_server+AMCL，定位不要求启动完整导航栈。现有旧launch的odom接线需改造，以下是**待实现的新接线设计**，不是现成可用命令。

```text
ESP32 /odom（原始） ───┐
ESP32 /imu/data ──────┼→ EKF → /odometry/filtered + TF odom→base_footprint
                     │
MS200 /scan ─────────┼→ 建图模式：slam_toolbox → /map + TF map→odom
                     └→ 执行模式：map_server + AMCL → /amcl_pose + TF map→odom

/odometry/filtered → M4局部路段执行器 → /cmd_vel → ESP32
固定动作序列 → M5状态机 ─────────────→ /lifter → ESP32
/map + /scan + TF + /amcl_pose → RViz与运行证据
```

## 话题和TF只设一个发布者

- M2保留原始`/odom`，EKF输入`odom0`明确指向`/odom`；EKF输出保留`/odometry/filtered`，不再映射回`/odom`，不加relay。`/imu/data`按已验证的安装方向与偏置接入。
- `odom→base_footprint`只由EKF发布，固件关掉这条TF广播；固件仍发布Odometry消息。静态车体/传感器TF由robot_state_publisher发布。
- `map→odom`在建图时由slam_toolbox发布，执行时由AMCL发布，两者互斥。
- `/cmd_vel`在自动执行时只由M4组件发布；建图遥控、手动兜底是独立互斥模式。AMCL、地图服务和RViz不发运动指令。
- `/map`、`/amcl_pose`、`/odometry/filtered`、TF是定位组件的标准内部输出，不算新增板端契约，不定义自制消息。

主路固定使用同一经验证的局部反馈源`/odometry/filtered`，避免训练/验收与比赛悄悄切换来源。开发时单独用原始odom做台架测试可以，但不记为建图定位与取放联合通过。若EKF接线无法及时稳定，M4可提出单一原始odom+TF方案重新冻结；不能双发布或自动静默切换。

## 定位如何参与执行

固定路线先用连续局部里程计闭环执行，AMCL提供真实的全局位置显示、日志与运行健康检查。第一版不将AMCL每次修正直接写进短距离控制，不依赖在线规划器，也不要求根据地图自动绕障。

每次重新摆车后，M4记录当前里程计到任务局部起点的变换；不靠把EKF/odom硬清零同步地图。场地测量坐标与地图坐标的对应由M3/M4在保存地图后标定，AMCL初始位姿使用实际地图坐标，不照抄旧图纸Start数值。AMCL定位用于自动路线纠偏只在主线稳定后作为可选项单独验证。

启动需地图已载入、首次定位已初始化、scan/局部反馈/必要TF新鲜且链路可用。运行时定位链路确实失效、scan断流或局部反馈失效则停车并记录；不因未达厘米级精度或正常粒子波动卡住任务。AMCL位姿消息可能随运动触发更新，不能用“每秒必须发若干条/amcl_pose”简单判死；同时检查scan、TF可用性、节点状态与实际运动响应，阈值由实测配置。

搬走货架后地图局部会变化；先实测AMCL是否仍能靠固定墙体保持可用，不为单个货架移动重新建整图，也不把局部变化直接判为定位失败。若持续错位，先检查初始位姿、外参、odom/TF接线与扫描遮挡，再考虑参数调优。

雷达同时用于经验证的近障停车；向前、后退、转向均按实测外形检查，带载遮挡与驶入货架通道需分别验证。该功能负责停，不负责自动重规划。

## 可复现的验收证据

M4交付真场地地图及参数、两种模式的启动/停止命令、唯一发布者检查、地图初始化流程；M3录制实车和RViz同步证据，M5归档。

必做三项：真实移动建图并重载；真实移动时地图定位响应；雷达/定位与固定路线取放同时运行。记录可见漂移、跳变和失败，不规定统一厘米阈值；位置明显不随车或长期失效不算通过。具体条目见[验收协议](../../tests/保守方案验收.md)的C14–C16。

里程碑：11-13完成接线、真移动建图和地图重载；11-15完成定位与单A架同时运行；11-18接四架；11-21整轮连续5次。现有真雷达/桌面图/mock测试保留为历史证据，不替代这些测试。
